# 应用数据同步

English: [data_sync.en.md](data_sync.en.md)

入口：**设置 → 存储与同步 → 数据同步**（未配置时亦可点击顶栏同步按钮）。填写 WebDAV 目录 URL、用户名和密码；目录大小写应与服务端一致。可先使用“测试连接”检查访问权限。

## 多设备合并与同步范围

新协议按**业务记录及字段的因果关系**合并，不再让用户在整包本地快照与云端快照之间二选一。不同设备离线新增不同收藏、阅读记录、已读章节或图片收藏，重新同步时可以保留双方内容；同一记录中互不冲突的字段也可合并。数据库和文件通过各自的业务适配器应用合并结果，而不是下载整个数据库覆盖本地。

| 数据领域 | 合并粒度与边界 |
|---|---|
| 收藏夹与漫画收藏 | 收藏夹使用稳定身份，改名不变成另一个收藏夹；收藏项按收藏夹、漫画及来源类型区分，名称、排序、漫画信息等字段分别合并。名称相同的独立收藏夹不会被强行合成一个；本地显示可作区分。“在读”角色绑定收藏夹身份。 |
| 阅读记录 | 按漫画及来源类型区分。漫画信息字段分别合并；**当前进度**的章节、页码、分组与时间是一个不可拆分的候选值，不拼接两个设备的位置，也不自动取最大页码。回读较早章节是有效修改；并发位置需要选定候选。 |
| 已读章节与图片收藏 | 每个已读章节、每张收藏图片分别作为记录；不同章节或图片的并发新增可以并存，而不是竞争同一个整章数组。同一漫画不同图片的字段差异会保留，不因本地共用一条展示记录而互相覆盖。 |
| 阅读时长 | 共同迁移的旧时长基数去重，不重复累加同一份历史；此后各设备新产生的正向增量累加，**不是取总时长的最大值**。重置、减少时长或不兼容的旧基数保留为需选择的候选，不静默丢弃。 |
| 设置 | 允许同步的设置按键及嵌套对象叶子合并；列表作为整体值。并发修改同一设置仍可能冲突。过滤规则见下文。 |
| 搜索历史 | 按关键词保留成员及稳定顺序；新增或再次搜索只更新该词的顺序，不重新编号其他旧词、制造虚假冲突。并发新词顺序相同时按关键词确定显示顺序。界面最多显示 50 条，不把未显示的其余条目当作已删除。 |
| Cookie | 按规范化域名同步完整 Cookie 会话；不逐个 Cookie 混拼两次登录。 |
| 漫画源脚本与会话 | 每个源的脚本版本作为整体，每个源的 `.data` 会话作为整体；不拼接脚本或登录状态。本地同身份别名若内容完全相同则自动折叠归一化，不产生虚假冲突；不同内容在删除旧运行时别名前先保存为持久同步候选；源 `.data` 会话不被归一化清除。 |

不包含本地漫画图片文件、下载漫画归档或在线漫画库中的图片。漫画归档备份和 WebDAV 在线漫画库仍是独立功能。

## 删除与逐项冲突

删除记录也有因果信息：已观察到的旧值可以被后续删除取代；**删除与另一设备未被观察到的编辑**会保留为冲突。删除父阅读记录与另一设备新增章节或图片等子记录时，也不能直接把新增内容清空。

即使明确选择删除父阅读记录，并发新增的已读章节仍会保留。为展示这些章节而保留的本地元数据容器不会被当作“重新创建阅读记录”同步；真正继续阅读后才产生新的阅读修改。

同一字段的兼容值可自动合并；互不兼容的并发值保留为持久候选，已有本地活动候选优先保持，直到明确处理。冲突界面按记录、字段及候选逐项选择，删除候选也可显式选择；一次选择不会全局覆盖其他记录。尚未解决的冲突不阻止其他无冲突记录合并，**传输成功不代表所有冲突已经解决**。同步不能保证任意并发设置、排序、脚本或会话编辑都能自动无冲突合并。

选择结果形成新的因果修改。双向或仅上传方向可发布该结果；仅下载方向将结果保留在本机待发布，需之后切换允许上传的方向才能共享。命令行用法见[无头命令模式](headless.zh.md)。

## 同步方向与时机

顶栏同步图标执行已选方向，实际排队工作期间旋转；未配置时打开设置。方向与时机相互独立：

| 方向 | 行为 |
|---|---|
| 双向（默认） | 捕获本地变更，读取并合并各设备的远端检查点，按业务记录应用结果，再发布待上传检查点。空服务器由本地数据初始化。 |
| 仅上传 | 发布本地因果检查点，不把其他设备的远端业务数据应用到本机。首次旧协议迁移可能读取旧档并纳入合并元数据，仍不导入本机业务数据；目录读取、校验或恢复操作不等于业务下载。 |
| 仅下载 | 读取并合并远端检查点，不发布本地检查点；本地修改仍被捕获并保留为候选，不把“仅下载”解释为强制云端覆写。 |

| 时机 | 触发方式 |
|---|---|
| 手动 | 明确同步操作或命令触发传输；保存配置本身不触发首次传输。 |
| 实时 | 除仅下载方向外，本地变更触发同步；启动与恢复前台也检查服务器，恢复检查至少间隔十分钟。 |
| 定时 | 每 5、15、30、60、180 或 360 分钟同步，默认 30 分钟。 |

定时模式合并间隔内多次变更；传输期间产生的新修改仍保留待同步。失败保留未完成工作，等待重试或后续调度。Timer 只随应用进程运行，不是系统后台保活服务，退出后不会唤醒系统；启动或恢复前台补做到期任务，系统暂停进程可能导致延迟。间隔从本次尝试结束重新计算。

同步、显式上传/下载、配置与冲突处理共用串行队列。命令不能绕过方向限制。网络读取和文件暂存期间继续追踪本地修改，提交前重新捕获并检查本地变更，避免等待网络期间的新编辑被旧目标替换。

## 离线、崩溃与失败恢复

本机持久状态按 WebDAV 端点绑定，保存设备身份、因果候选、已观察记录及待上传队列（outbox）。捕获的修改先落盘，再进行网络发布；远端应用目标以 `pendingApply` 与合并元数据一同原子保存，再写入业务数据库和文件。启动时先恢复未完成应用，并保留恢复时实际本地数据中的修改，再继续捕获与同步。

状态文件有可恢复备份；元数据损坏不会被当作全新空状态静默重置。使用备份恢复时可能需要验证远端状态以防设备计数器倒退；验证失败会报告错误，而不是冒险继续。这不是跨进程或跨多个数据库/文件的单一事务，崩溃后依靠持久应用日志恢复。

认证失败、网络错误或应用失败会报告失败，未完成的发布/应用继续保留。若部分远端发布或本地业务提交已经成功，后续阶段失败**不会假称已回滚这些已提交内容**；重试从持久状态继续，避免把已提交工作误当作从未发生。

本地漫画源归一化同样受持久日志保护：在旧别名与新规范文件并存的中间状态下，日志恢复具备幂等性，重复恢复绝不复活已显式解决的候选；本地物理文件归一化遵循同步方向边界，不会在仅上传等受限模式下越界导入未应用的远端业务数据。真实文件系统故障或非法脚本解析错误仍会严格报错阻断。

若启动恢复失败，纠正故障后再次发起同步会重新执行恢复，不会因缓存的启动错误永久拒绝请求；恢复成功前不执行后续上传、下载或冲突处理。

## 云端格式与完整性

新协议使用独立的 **`sync-v2/`** 目录，发布文件按 `actor-counter-SHA256.json` 命名。每份文件是不可变的**完整因果检查点**，包含已知记录、候选和删除信息；它不是原始数据库覆盖包，也**不是只传变更的网络增量批次**。逐记录合并不意味着每次只上传几个字段，数据量仍受完整检查点大小影响。

读取时验证文件名字中的 SHA-256、内容格式及设备/计数器一致性；GET 重定向或缺少 ETag 仍可通过内容哈希验证。内容损坏或未写完的候选文件不是已提交检查点，不能遮蔽该设备较旧的有效检查点；同计数器的多个文件不能随意挑一个。认证或网络故障则是真实错误，不能当作“没有远端数据”。

上传使用条件创建，并回读校验后才确认完成。若重试发现本设备先前留下的坏文件，只能在验证并具备强 ETag 条件保护时修复，或发布包含原意图的替代检查点；不能无条件覆盖，也不能把碰撞或截断当作成功。安全清理仅针对上传前已发现、可证明被新检查点因果覆盖的**本设备**旧文件，并要求强 ETag 与 `If-Match`；其他设备、并发新文件及旧 `.venera` 档不在清理范围。缺少条件校验值时可能保留更多文件。

## 设备本地字段与秘密边界

以下内容不参与普通数据同步，远端内容也不能覆盖本机值：

- 数据同步 WebDAV URL、用户名、密码及连接偏好。
- 当前设备的同步方向、时机、间隔、排除字段配置，以及设备身份、待同步标记和合并/恢复元数据。
- 本地漫画存储路径（`local_path`）、设备专属设置、代理及本机安全设置等被过滤字段。
- Bangumi Access Token、用户名、待提交进度及失败重试队列。

用户排除的设置和未开启同步的可选设置属于**不同步**，不是删除指令；关闭开关不应向其他设备发布这些设置的删除，也不会借远端导入改写本机被排除的值。

WebDAV 漫画库配置和漫画归档备份的 WebDAV 配置分别有独立的同步开关，默认关闭；只有导出端与导入端分别主动开启对应开关，地址及凭据才可传输并应用。开关本身仍属本机配置。**这些可选凭据、Cookie 与漫画源会话可能包含秘密，获准同步后会存在云端检查点中**，请仅使用可信且访问受控的 WebDAV 服务。冲突界面和 CLI 只提供安全摘要，不输出原始 Cookie、会话、脚本正文或敏感设置候选；脱敏显示不等于云端加密。

## 保存配置与旧协议升级

保存配置先验证连接并准备端点状态，**不先上传或导入业务数据**。验证或提交前保存失败保留旧连接、偏好及本机业务数据。保存成功表示配置已提交；实时或定时模式随后将首次同步放入普通队列，手动模式只保存配置。之后传输失败会保留已保存配置、待完成工作及错误状态，不把已保存配置或已提交的数据假回滚为旧值。

修改时机或间隔会重新排期；清空所有连接字段后保存可断开同步。旧版自动同步开启迁移为实时、关闭迁移为手动，已有定时模式保留；旧键一次性移除。方向默认双向。

首次连接某端点时，根目录旧格式 `.venera` 同步档仅作为**一次性迁移种子**：在隔离目录校验后读取所有最高数字版本的档案，同版本不同文件都保留为种子/候选，不擅自选择一个，也不删除旧档。迁移读取或校验失败不会标记为已完成；之后旧版客户端继续写根目录的内容不会自动混入新协议。

首次旧格式迁移有资源校验限制：每份档案下载最多 512 MiB、展开内容合计最多 1 GiB，单数据库最多 256 MiB、单文本文件最多 16 MiB，最多 10,000 个条目，中央目录元数据最多 8 MiB。超限会明确报错并中止整个迁移，不截断数据、不导入部分种子、不覆盖本地数据，也不标记迁移完成。请保留原备份/档案；当前没有提供调高这些限制的用户选项。

**共享合并同步的所有设备都必须升级到支持 `sync-v2` 的客户端。** 旧客户端仍使用根目录整包协议，两种协议不会持续互通。升级前可手动导出 `.venera` 留存备份。手动 `.venera` 导入/导出仍是独立的备份恢复功能，不等于“强制上传/下载覆写”，也不是选择整个同步冲突版本的替代命令。
