# 应用数据同步

English: [data_sync.en.md](data_sync.en.md)

入口：**设置 → 存储与同步 → 数据同步**（未配置时亦可点击顶栏同步按钮）。填写 WebDAV 目录 URL、用户名、密码和设备名；目录大小写应与服务端一致。设备名默认读取 Android 型号、iOS 设备名称或桌面主机名，允许修改。名称配置只在本机生效，但同步目录和设备元数据会携带名称，请勿填写敏感信息。可先使用“测试连接”检查访问权限。

## 多设备合并与同步范围

新协议按**业务记录及字段的因果关系**合并，不再让用户在整包本地快照与云端快照之间二选一。不同设备离线新增不同收藏、阅读记录、已读章节或图片收藏，重新同步时可以保留双方内容；同一记录中互不冲突的字段也可合并。数据库和文件通过各自的业务适配器应用合并结果，而不是下载整个数据库覆盖本地。

| 数据领域 | 合并粒度与边界 |
|---|---|
| 收藏夹与漫画收藏 | 收藏夹使用稳定身份，改名不变成另一个收藏夹；收藏项按收藏夹、漫画及来源类型区分，名称、排序、漫画信息等字段分别合并。名称相同的独立收藏夹不会被强行合成一个；本地显示可作区分。主页展示与自动追更共用的收藏角色（`reading`）绑定收藏夹身份，默认未绑定，可由用户选择任意本地收藏夹。 |
| 阅读记录 | 按漫画及来源类型区分。漫画信息字段分别合并；**当前进度**的章节、页码、分组与时间是一个不可拆分的候选值，不拼接两个设备的位置，也不自动取最大页码。同一位置、其他内容也相同而只有有效时间戳不同的候选自动保留较新时间；真实位置差异仍需选择。回读较早章节是有效修改。 |
| 已读章节与图片收藏 | 每个已读章节、每张收藏图片分别作为记录；不同章节或图片的并发新增可以并存，而不是竞争同一个整章数组。同一漫画不同图片的字段差异会保留，不因本地共用一条展示记录而互相覆盖。 |
| 阅读时长 | 共同迁移的旧时长基数去重，不重复累加同一份历史；此后各设备新产生的正向增量累加，**不是取总时长的最大值**。重置、减少时长或不兼容的旧基数保留为需选择的候选，不静默丢弃。 |
| 设置 | 允许同步的设置按键及嵌套对象叶子合并；列表作为整体值。并发修改同一设置仍可能冲突。过滤规则见下文。 |
| 搜索历史 | 按关键词保留成员及稳定顺序；新增或再次搜索只更新该词的顺序，不重新编号其他旧词、制造虚假冲突。并发新词顺序相同时按关键词确定显示顺序。界面最多显示 50 条，不把未显示的其余条目当作已删除。 |
| Cookie | 按规范化域名同步完整 Cookie 会话；不逐个 Cookie 混拼两次登录。 |
| 漫画源脚本与会话 | 每个源的脚本版本作为整体，每个源的 `.data` 会话作为整体；不拼接脚本或登录状态。本地同身份别名若内容完全相同则自动折叠归一化，不产生虚假冲突；不同内容在删除旧运行时别名前先保存为持久同步候选；源 `.data` 会话不被归一化清除。 |
| Bangumi | Access Token、用户名、同步偏好及漫画条目绑定参与设置同步；绑定包含条目信息、话/卷进度和评分。待提交进度与失败重试队列留在本机，不通过 WebDAV 转移。 |

不包含本地漫画图片文件、下载漫画归档或在线漫画库中的图片。漫画归档备份和 WebDAV 在线漫画库仍是独立功能。

### 分类范围

设置中可独立开关以下七组，默认全部开启；已有的可选 WebDAV 凭据开关仍默认关闭：

| 分类 | 包含内容 |
|---|---|
| 设置 | 允许同步的应用设置 |
| 收藏 | 收藏夹、漫画收藏及收藏角色绑定，作为一组 |
| 阅读记录 | 阅读进度、时长和已读章节，作为一组 |
| 图片收藏 | 图片收藏记录，不包含原始图片文件 |
| 搜索历史 | 关键词及顺序 |
| 漫画源脚本 | 漫画源脚本版本 |
| 登录状态 | Cookie 与漫画源 `.data` 会话，作为一组 |

关闭分类停止该领域的新变更捕获和远端应用，**不是删除命令**，也不会撤回已捕获的待上传内容或擦除云端旧候选。范围配置只保存在本机。登录状态分类不包含 Bangumi Token 等设置项；这些项的秘密边界见下文。

## 删除与集中冲突选择

删除记录也有因果信息：已观察到的旧值可以被后续删除取代；**删除与另一设备未被观察到的编辑**会保留为冲突。删除父阅读记录与另一设备新增章节或图片等子记录时，也不能直接把新增内容清空。

即使明确选择删除父阅读记录，并发新增的已读章节仍会保留。为展示这些章节而保留的本地元数据容器不会被当作“重新创建阅读记录”同步；真正继续阅读后才产生新的阅读修改。

兼容的字段值自动合并，互不兼容的并发值保留为持久候选，已有本地活动候选优先保持，直到明确处理。冲突界面支持按分类分组、搜索和“仅未选择”筛选，可对当前筛选结果批选本机当前值，或批选指定设备的候选；没有匹配候选的项目不会被猜测选择。候选展示设备名、可用的时间和安全摘要，区分字段删除与整条记录删除。

**不必全部选完**：点击“确认所选”仅提交已选项，剩余冲突继续保留，可分批处理。选择过程中不应用或上传，关闭界面丢弃未提交选择。如果候选在确认前发生变化，须重新选择，不会静默覆盖新到达的修改。所选批次统一校验后以一个持久提交保存；之后应用或上传失败会明确提示恢复状态，而不假称已回滚。未解决的冲突不阻止无冲突记录合并，**传输成功不代表所有冲突已解决**。

按设备批选后，可主动记住该设备作为普通设置冲突的优先候选；默认不记忆。偏好仅对该设备确有候选的普通设置生效，不自动处理秘密、删除、脚本、会话或真实阅读位置差异，也不是“总取最新时间”。可从同步设置的冲突入口清除偏好，包括当前已无冲突时。同步不能保证任意并发设置、排序、脚本或会话编辑都能自动无冲突合并。

冲突标题、说明和候选列表可滚动查看；窄屏或放大字体时，底部操作会换行，关闭与确认操作保持可达。

选择结果形成新的因果修改。双向或仅上传方向可发布该结果；仅下载方向将结果保留在本机待发布，需之后切换允许上传的方向才能共享。命令行用法见[无头命令模式](headless.zh.md)。

## 同步方向与时机

顶栏同步图标执行已选方向，实际排队工作期间旋转；未配置时打开设置。方向与时机相互独立：

| 方向 | 行为 |
|---|---|
| 双向（默认） | 捕获本地变更，读取并合并各设备的远端检查点，按业务记录应用结果，再发布待上传检查点。空服务器由本地数据初始化。 |
| 仅上传 | 发布本地因果检查点，不把其他设备的远端业务数据应用到本机。首次旧协议迁移可能读取旧档并纳入合并元数据，仍不导入本机业务数据；目录读取、校验或恢复操作不等于业务下载。 |
| 仅下载 | 读取并合并远端检查点，不发布本地检查点；本地修改仍被捕获并保留为候选，不把“仅下载”解释为强制云端覆写。 |

| 时机 | 触发方式 |
|---|---|
| 手动 | 明确同步操作或命令触发传输；保存配置本身不触发首次传输。 |
| 实时 | 真实本地变更合并后上传；无实际变化的保存、单纯切页和设备本地字段保存不发布检查点。远端检查独立进行，应用运行期间约每十分钟一次，启动/恢复前台补做到期检查。仅下载方向不因本地变化上传。 |
| 定时 | 每 5、15、30、60、180 或 360 分钟同步，默认 30 分钟。 |

实时上传在最后一次变更后等待 **10 秒**，两次自动上传尝试至少间隔 **60 秒**；持续编辑时，正常可运行状态下等待最多 **2 分钟**便安排本批次。离开阅读器或应用进入后台时会请求刷新待处理修改，但不绕过方向、最小间隔或失败退避，也不保证系统会继续运行进程。手动同步立即进入串行队列，不受这些自动等待限制。

定时模式合并间隔内多次变更，间隔从本次尝试结束重新计算。传输期间产生的新修改保留待同步。自动失败使用逐步退避；认证错误暂停自动重试，修正凭据并保存配置或手动重试后再继续。Timer 只随应用进程运行，不是系统后台保活服务，退出后不会唤醒系统；启动或恢复前台补做到期任务，系统暂停进程可能导致延迟。

设置页显示实际待发布记录数、冲突数、最近成功时间、触发原因及本次上传/下载字节与对象数，并提供“立即同步”和经确认的旧版变更导入入口。计数不通过读取秘密正文生成，待发布数不是队列批次数；已有数据尚未完成捕获时，持久队列计数不代表所有未保存的界面修改。

同步、显式上传/下载、配置与冲突处理共用串行队列。命令不能绕过方向限制。网络读取和文件暂存期间继续追踪本地修改，提交前重新捕获并检查本地变更，避免等待网络期间的新编辑被旧目标替换。

## 离线、崩溃与失败恢复

本机持久状态按 WebDAV 端点绑定，保存设备身份、因果候选、已观察记录及待上传队列（outbox）。捕获的修改先落盘，再进行网络发布；远端应用目标以 `pendingApply`、实际可应用的领域及合并元数据一同原子保存，再写入业务数据库和文件。启动时先恢复未完成应用，并保留恢复时实际本地数据中的修改，再继续捕获与同步。受阻领域保留各记录原有的因果观察，不因其他领域同步了同一设备的后续修改而提前覆盖未观察的源候选。

合并元数据使用按记录存储的 SQLite，待上传队列引用不可变清单与压缩对象，不再在每次保存时重写一个巨大状态 JSON。主库与恢复副本通过 SQLite 附加数据库事务一起增量更新，常规提交不复制整个数据库；文件级修复仅用于初始化或恢复。旧本地 JSON 状态只读迁移并保留原文件。

损坏元数据不会被当作全新空状态静默重置；恢复会校验版本与设备身份，必要时验证远端状态以防设备计数器倒退。验证失败会报告错误而非冒险继续。这里的主备事务**不等于**收藏、历史、偏好与源文件之间存在一个跨业务库/文件的全局事务；业务应用仍依靠持久日志恢复。

认证失败、网络错误或应用失败会报告失败，未完成的发布/应用继续保留。若部分远端发布或本地业务提交已经成功，后续阶段失败**不会假称已回滚这些已提交内容**；重试从持久状态继续，避免把已提交工作误当作从未发生。

本地漫画源归一化同样受持久日志保护：在旧别名与新规范文件并存的中间状态下，日志恢复具备幂等性，重复恢复不复活已显式解决的候选；本地物理文件归一化遵循同步方向边界，不会在仅上传等受限模式下越界导入未应用的远端业务数据。真实业务提交失败仍会报告失败并保留待恢复状态。

若启动恢复或本地元数据事务失败，纠正故障后再次发起同步会重新加载持久状态并恢复，不必通过重启或清空状态绕过错误；恢复成功前不执行后续上传、下载或冲突处理。

## 异常漫画源与部分同步

空脚本、语法损坏、无法可靠确定身份或损坏会话会显示为源异常，而不是把缺失内容当作删除。无法完整捕获的 `source`（脚本）或 `sourceSession`（会话）领域暂停捕获和应用，保留原观察值；设置、收藏和历史等完整领域仍可同步。顶栏与设置页会提示**部分同步**，不把传输成功等同于所有源均已恢复。

脚本与会话的完整性分别判断。仅 `.data` 会话损坏时，有效脚本仍可参与同步；依赖该会话的源运行时重载会延后，直到会话恢复。不拼接不同登录状态，也不为消除错误而清空会话。

自动恢复只使用可证明属于同一稳定身份的有效本地脚本、已验证备份或已应用记录，不凭 `komiic.js`、`jm(0).js` 等文件名猜测身份。隔离探测仅提供纯随机数和 UUID 辅助 API，不访问真实网络、文件或会话；探测环境受限的脚本与真正损坏的文件分开报告，不自动替换受限脚本。没有可信恢复内容时，原文件保留在原处并暂停相关领域。

可从异常源对话框选择可信文件修复脚本、会话或元数据。替换先验证内容并检查原文件未被并发修改，再保存不可变的原始文件证据并提交；无效替换不会覆盖现有内容。有原始备份时可导出留存，但损坏备份不是可直接恢复的有效脚本。若提示文件已保存、仍等待运行时恢复，说明文件提交已完成；修复依赖问题后重试，不要把后续同步失败当成文件已回滚。

恢复日志损坏或不完整时，先导出原始文件和备份，恢复与当前隔离记录相匹配的完整日志后重试。**不要删除日志、清空同步状态或重新安装源来绕过日志校验**；缺少完整证明时不会冒险完成替换或发布删除。

## 云端格式与完整性

新协议位于用户填写的 WebDAV 目录下的 **`VeneraPlus/sync-v4/设备名/`**，与旧单文件检查点隔离：

```text
VeneraPlus/sync-v4/设备名/
  device.json
  commits/计数器-清单SHA256.json
  objects/数据领域/对象SHA256.json.gz
```

每个提交清单描述一个**完整因果检查点**，保留记录、候选与删除信息，但不再把全部内容塞入一个 JSON。内容按数据领域 gzip 压缩，收藏、历史等大集合按稳定身份分入 64 个桶，脚本、会话及 Cookie 按各自身份独立存储；全局因果时钟位于清单，避免仅计数器变化就改变所有分片。

先上传和验证所需对象，最后发布不可变清单。内容寻址允许复用未变化的对象：只改一个设置通常只上传设置对象及新清单，不重传历史或脚本。接收端使用按端点隔离、经过校验的内存和磁盘对象缓存，重启后仍可复用已下载对象。这是**分片级增量传输**，不是逐字段网络补丁；首轮或空缓存仍需下载所需对象，清单和目录发现也有开销。

设备名中的路径分隔符、URL 特殊字符及控制字符会替换为下划线，末尾不安全的点和空格会移除；空名及纯点路径不可使用。同名设备若目录已归另一设备所有，会在目录名后附加稳定短标识，不覆盖其他设备。改名不改变内部设备身份和计数器；旧目录仍参与发现，检查点按相同规则读取与安全清理。同步会读取各设备目录，不局限于本设备目录。已有本地同步状态即使没有新修改，在本设备尚无新目录检查点时也会发布完整检查点。

读取时验证文件名中的 SHA-256、内容格式、计数器以及目录所有权与文件中设备身份的一致性；GET 重定向或缺少 ETag 仍可通过内容哈希验证。内容损坏或未写完的候选文件不是已提交检查点，不能遮蔽该设备较旧的有效检查点；同计数器的多个文件不能随意挑一个。认证或网络故障则是真实错误，不能当作“没有远端数据”。

上传使用条件创建，并回读校验后才确认完成。清单与对象均验证 SHA-256、格式、领域、路径和资源限制；若清单引用的对象不完整，不把该清单当作可用提交。若重试发现本设备先前留下的坏文件，只能在验证并具备强 ETag 条件保护时修复，或发布包含原意图的替代检查点；不能无条件覆盖，也不能把碰撞或截断当作成功。

清理仅针对上传前已发现、可证明被新检查点因果覆盖的**本设备旧提交清单**，要求强 ETag 与 `If-Match`，并保留一个有效前序恢复点。其他设备、并发新文件、旧协议检查点及 `.venera` 档不在清理范围。**压缩对象与删除因果信息暂不自动清理**：普通 WebDAV 无法证明没有并发清单仍将引用对象，离线设备也可能携带旧值。因而云端占用不会保证恒定；缺少条件校验值时会保留更多旧清单。

## 设备本地字段与秘密边界

以下内容不参与普通数据同步，远端内容也不能覆盖本机值：

- 数据同步 WebDAV URL、用户名、密码及连接偏好。
- 当前设备的同步方向、时机、间隔、设备名配置、分类范围、排除字段、设置冲突设备偏好，以及设备身份、待同步标记和合并/恢复元数据。远端设备所有权与因果身份不等于覆盖本机配置。
- 本地漫画存储路径（`local_path`）、设备专属设置、代理及本机安全设置等被过滤字段。
- Bangumi 待提交进度及失败重试队列。

用户排除的设置和未开启同步的可选设置属于**不同步**，不是删除指令；关闭开关不应向其他设备发布这些设置的删除，也不会借远端导入改写本机被排除的值。

Bangumi Access Token、用户名和条目绑定默认参与同步，可通过排除字段配置禁用对应设置。**Access Token 会保存在远端检查点中**，请仅使用可信的 WebDAV 服务；界面和 CLI 对 Token 候选进行脱敏，但云端文件并未因此加密。

WebDAV 漫画库配置和漫画归档备份的 WebDAV 配置分别有独立的同步开关，默认关闭；只有导出端与导入端分别主动开启对应开关，地址及凭据才可传输并应用。开关本身仍属本机配置。**这些可选凭据、Cookie 与漫画源会话可能包含秘密，获准同步后会存在云端对象中**，请仅使用可信且访问受控的 WebDAV 服务。冲突界面和 CLI 只提供安全摘要，不输出原始 Cookie、会话、脚本正文或敏感设置候选。**gzip 是压缩，不是加密**；脱敏显示和关闭分类也不会擦除已存储的云端秘密。

## 保存配置与旧协议升级

保存配置先验证连接并准备端点状态，**不先上传或导入业务数据**。验证或提交前保存失败保留旧连接、偏好及本机业务数据。保存成功表示配置已提交；实时或定时模式随后将首次同步放入普通队列，手动模式只保存配置。之后传输失败会保留已保存配置、待完成工作及错误状态，不把已保存配置或已提交的数据假回滚为旧值。

修改时机或间隔会重新排期；清空所有连接字段后保存可断开同步。旧版自动同步开启迁移为实时、关闭迁移为手动，已有定时模式保留；旧键一次性移除。方向默认双向。

首次使用新布局时，会验证并一次性合并旧 **`VeneraPlus/设备名/计数器-SHA256.json`** 检查点，记录已迁移清单，并在允许上传时发布到 `sync-v4`。旧文件只读保留，不原地改写；最高检查点不完整或读取失败时，不把迁移标记为完成。仅下载方向可保留待发布桥接状态，但不会越权上传。

迁移后若发现旧客户端新写入的检查点，会暂停普通同步并要求处理，不静默把两种持续写入的协议混在一起。先升级或停用旧客户端，再从设置选择“导入旧版变更”并确认；该操作重新验证旧检查点、导入新增内容并更新迁移清单。没有新增旧检查点时不会假称导入了新数据。

首次连接某端点时，根目录旧格式 `.venera` 同步档仅作为**一次性迁移种子**：在隔离目录校验后读取所有最高数字版本的档案，同版本不同文件都保留为种子/候选，不擅自选择一个，也不删除旧档。可用业务领域分别完成迁移，异常源相关领域保留待恢复状态；读取或完整性校验失败不会标记迁移完成。之后旧版客户端继续写根目录的内容不会自动混入新协议。

首次旧格式迁移有资源校验限制：每份档案下载最多 512 MiB、展开内容合计最多 1 GiB，单数据库最多 256 MiB、单文本文件最多 16 MiB，最多 10,000 个条目，中央目录元数据最多 8 MiB。超限会明确报错并中止整个迁移，不截断数据、不导入部分种子、不覆盖本地数据，也不标记迁移完成。请保留原备份/档案；当前没有提供调高这些限制的用户选项。

旧档兼容原生 ZIP64 目录及带签名/无签名的 32、64 位数据描述符，仍严格校验 CRC、局部头与中央目录一致性、路径、条目边界和展开限制；损坏或截断包不会因兼容 ZIP64 而放行。旧档中的异常源可通过档案 SHA-256 和条目路径绑定的**持久本地修复覆盖层**恢复；重试在隔离目录应用覆盖层，不改写云端 `.venera` 或原始验证备份，修复后只补充尚未完成迁移的领域。

**共享同步的所有设备都应升级到 `VeneraPlus/sync-v4/设备名/` 协议。** 旧 `VeneraPlus/设备名/` 因果检查点支持上述受控迁移，根目录 `.venera` 仍仅作一次性种子；旧 `sync-v2/` 不读取、不迁移，也不自动删除。旧客户端不会与新布局持续互通。升级前可手动导出 `.venera` 留存备份；仅存在于旧 `sync-v2/`、尚未导入本机的数据须先用旧客户端同步到本机或导出备份。手动 `.venera` 导入/导出仍是独立的备份恢复功能，不等于“强制上传/下载覆写”，也不是选择整个同步冲突版本的替代命令。
