# Bangumi 多源作品聚合

English version: [bangumi_groups.en.md](bangumi_groups.en.md)

将不同来源的漫画分别绑定到同一个 Bangumi 条目后，主页、本地收藏和阅读历史会将它们显示为一部作品。卡片优先采用已保存的 Bangumi 标题、封面，并显示来源数量；缺少条目标题或封面时使用来源信息。

## 建立和解除分组

1. 在漫画详情页的 Bangumi 功能中选择条目并完成绑定。
2. 为另一来源的同一作品绑定相同的 Bangumi ID。
3. 返回主页、收藏或历史，即可看到合并后的卡片。

分组只依据已保存的有效绑定。相似标题、条目搜索结果或元数据候选不会直接建立分组。解除绑定或改绑其他条目后，列表会重新分组；关闭自动同步或断开 Bangumi 账号不会删除已有分组。在线漫画库仍按当前库的绑定范围识别漫画。

主页只展示绑定收藏夹内的来源；普通本地收藏夹也只合并当前夹内的成员。“全部”收藏会合并各夹中同一作品的记录。收藏夹侧栏保留来源记录数，悬停或长按计数可查看说明，因此它可能大于分组后的卡片数。

## 阅读和切换来源

- 继续阅读优先使用有阅读记录且当前可用的最近来源。多个来源均无历史时，先选择来源。
- 使用卡片菜单或详情页中的“选择漫画来源”可主动切换。选择器显示各来源的阅读进度、最近阅读标记、下载和更新状态。
- 每个来源保留自己的章节、页码和阅读位置。新来源没有历史时，从其详情和目录开始；已有本地下载且源不可用时，可通过本地阅读入口继续。
- 来源无法访问且没有本地下载时，选择器会标记为不可用。

切换来源不会把原来源的章节序号或页码套用到目标来源，也不会合并下载文件。任一来源有更新时，作品卡片显示更新提醒；正常阅读只清理对应来源的提醒。组菜单中的“清除所有来源的更新提醒”会清理当前组内各来源的提醒。

## 搜索、收藏管理和历史

搜索支持 Bangumi 标题、原名，以及任一来源的名称和标签；命中后保留整组。全选和反选以当前搜索、阅读状态和屏蔽过滤后的可见作品为准。阅读状态依据最近阅读来源的记录，不代表整部作品已经完结。

复制、移动或删除作品时，只处理当前收藏夹内的组成员；其他收藏夹独有的来源不会被顺带处理。排序以作品为单位，保存时将成员连续排列。下载仍须明确选择来源。绑定或组成员改变时，会清理可能失效的选择，避免扩大批量操作范围。

历史保留每个来源的原始记录。可以删除整部作品的阅读历史，也可以选择并删除某个来源的历史，包括已经不可用的来源。

## Bangumi 同步

在“设置 → 在线服务 → Bangumi”的“网址列表”中选择服务地址，默认使用官方 `bgm.tv`，并预置 `bangumi.lat` 与 `anibt.net` 镜像。列表显示名称或主域名，各站点分别保存实际 API、图片反代和 Token 页面地址，不按子域名规则猜测。

添加自定义地址时填写实际 API 地址，可省略 `https://`；名称、图片反代和 Token 申请页面可选。图片反代留空时沿用 API 返回的图片地址，Token 页面留空时打开官方申请页面。保存后追加到列表末尾，点击该项即可切换；自定义项支持编辑和删除，删除当前使用项会恢复官方地址。所选 API 服务器会接收账号的 Access Token，请选择自己信任的服务。

每次打开列表会自动检测各 API，也可手动重新测试。延迟是当前设备按应用网络设置发起一次匿名公开接口请求的耗时；检测不会向所有地址发送 Token。验证页、超时和不兼容响应会单独标记，公开接口可用不代表账号同步已经通过验证，可使用页面中的“验证连接”检查当前账号。关闭列表会取消剩余检测。

同一 Bangumi 条目的已绑定漫画共用远端话数、卷数、评分和收藏状态。更新某一来源后，同条目的本地缓存一并更新。各来源的进度解析方式保持独立；本地章节和页码不跨来源同步。

手动回退进度会清理同一账号、同一条目、同一进度字段的冲突待上传任务，防止旧任务立即将进度推回去。后续实际阅读仍可产生新的上传进度。应用数据的跨设备同步规则见[应用数据同步](data_sync.zh.md)。
